# Phase 3A.5 — Raw Dataset Validation and Consolidation

**Date of validation:** 2026-09-13
**Scope:** Validate the raw Tomato (official Agmarknet, manually exported) and Potato (CEDA, Phase 3A.4) datasets, and produce clean, reproducible, non-fabricated processed datasets for the common study window 2025-03-05 to 2025-09-07.
**Rule followed throughout:** no raw file under `data/raw/` was modified, renamed, or deleted. No missing date was filled or interpolated. No suspicious value was silently removed. Every number below comes from actually running `scripts/phase3a5_validate_and_consolidate.py` against the real files — nothing is estimated.
**Reproducibility:** every result in this report can be regenerated by running `scripts/phase3a5_validate_and_consolidate.py` from the project root. It only reads `data/raw/` and only writes `data/processed/`.

---

## 1. Phase Objective

Phase 3A.4 produced real Potato historical data from CEDA and specified a manual Tomato acquisition requirement (official Agmarknet 2.0, Bowenpally APMC, CAPTCHA solved by a human). That manual export has now been performed and delivered as six monthly CSV files. This phase's job is narrow and mechanical, not exploratory: inspect exactly what was actually delivered in both raw sources, validate it against concrete, checkable criteria, and produce two clean processed CSVs — without inventing, interpolating, or silently discarding anything. This phase does not begin ML modeling.

## 3. Tomato Dataset Validation

**File structure (all six files, confirmed identical):** two title/metadata lines (e.g. `"Date Wise Prices for Specified Commodity on March, 2025 for Commodity : Tomato, State/UT : Telangana"`), one blank line, one header row (`Arrival Date,Arrivals (Metric Tonnes),Variety,Minimum Price (Rs./Quintal),Maximum Price (Rs./Quintal),Modal Price (Rs./Quintal)`), then a sequence of market sections. Each section begins with a line of the form `Market Name : <market>` (some market names are quoted because they contain commas, e.g. `"Market Name : Pavilion Ground,Khammam,RBZ"`) followed directly by that market's daily rows — **the header is not repeated per market**, so a correct parser must track which market section it is currently inside.

**VALIDATED FACTS** (from actually running the extraction and checks in `scripts/phase3a5_validate_and_consolidate.py`):
1. Every file contains multiple markets (19–21 per file) — confirming the raw export is state-wide, not Bowenpally-only, exactly as the task description warned.
2. Bowenpally APMC is present in 5 of 6 files (March, April, May, June, August) and **absent entirely from July's file**.
3. Commodity is consistently "Tomato" throughout (the header/title explicitly scopes the file to Tomato; individual rows do not repeat the commodity name, so this is a file-level fact, not a per-row-verified one for Bowenpally specifically — though the variety field being uniformly "Deshi" tomato is consistent with this).
4. Variety for every one of the 103 extracted Bowenpally rows is **"Deshi"** — no other variety appears for this market.
5. Date format is `DD/MM/YYYY` throughout; all 103 dates parsed successfully with `strptime("%d/%m/%Y")` — zero invalid dates.
6. Price unit, per the header, is **Rs./Quintal** for min/max/modal; arrivals are in **Metric Tonnes**.
7. Column count is exactly 6 for all 103 rows — zero structural anomalies.
8. **Zero duplicate dates** across all 103 Bowenpally rows (combined across all 6 files).
9. **Zero `min <= modal <= max` violations** and **zero negative values** across all 103 rows.
10. Chronological ordering within each file's Bowenpally block is strictly ascending by date with no out-of-order rows (verified by inspection of each block, not assumed from file layout).

**POTENTIAL DATA QUALITY ISSUES** (reported, not fixed):
1. **June 2025: only 3 Bowenpally rows** (01/06–03/06), then nothing for the rest of the month in this export. Whether this reflects an actual reporting gap at the source, a partial/incomplete export, or a genuine market closure cannot be determined from this file alone.
2. **July 2025: Bowenpally APMC does not appear in the file at all.** This is a complete month of zero coverage, not a small gap.
3. Combined with #1 and #2, there is one continuous span of **66 missing calendar days (2025-06-04 to 2025-08-08)** with zero Bowenpally data anywhere in the raw files.
4. **No September file exists**, so 2025-09-01 through 2025-09-07 (7 days, the tail of the target study window) has no Tomato coverage from this source.
5. May's Bowenpally block starts on 02/05/2025, not 01/05 — the first day of May is itself missing, consistent with (not contradicting) the broader gap pattern.
6. This report cannot verify whether "Bowenpally APMC" is spelled/identified identically across all six files at the source system level beyond string matching "Bowenpally" in the market-name line — this matched cleanly in all 5 files where the market appears, with no near-miss variant spellings observed, but this is a string-match result, not an independent confirmation against a market-ID system (unlike CEDA/official-API reference data, these CSV exports carry no numeric market ID).

## 4. Potato Dataset Validation

**Explicit, non-negotiable framing, per this phase's instructions: this is Hyderabad district-level proxy data. It is NOT Bowenpally-mandi-level data, and it is not described as such anywhere in this report or in the processed output.**

**VALIDATED FACTS:**
1. Schema, confirmed from the actual JSON files: `{"data": [{"t": <date>, "cmdty": "Potato", "district_id": 536, "district": "Hyderabad", "p_min": <float>, "p_max": <float>, "p_modal": <float>}, ...]}` — no market/mandi field exists anywhere in this schema (re-confirming Phase 3A.4's Section 2 finding).
2. 178 total records across all 7 files.
3. 178 unique dates — **zero duplicate dates**, confirmed both within and across the 7 files.
4. Date range: 2025-03-05 to 2025-09-07 (the full target window, with no leading/trailing overshoot unlike the Tomato files).
5. Commodity field is uniformly `"Potato"` across all 178 records — no stray values.
6. District field is uniformly `"Hyderabad"` across all 178 records.
7. Price fields present: `p_min`, `p_max`, `p_modal`. These are **non-integer values** (e.g. `1266.6666666666667`), which is itself evidence they are computed averages across multiple reporting mandis within the district, not a single market's raw reported figure — this is exactly why this data cannot be described as mandi-level.
8. **Zero `p_min <= p_modal <= p_max` violations** and **zero negative values** across all 178 records.
9. Units are not explicitly labeled by the CEDA API response itself; they are treated as ₹/quintal by convention (consistent with the official Agmarknet Tomato export's explicit unit label and with this project's existing price figures), which is an inference carried over from Phase 3A.2/3A.3, not a field the API states directly.

**POTENTIAL DATA QUALITY ISSUES:**
1. 9 missing dates within the 187-day study window (Section 5) — small relative to Tomato's gap, but present.
2. No independent confirmation of exactly which mandis' data was averaged into a given day's district figure — this is a structural limitation of the source, not something this validation pass can resolve.

## 7. Unit Consistency

| Field | Tomato (official Agmarknet) | Potato (CEDA) |
|---|---|---|
| Price unit | **Explicitly labeled** in the file header: `Rs./Quintal` | **Not explicitly labeled** by the API; treated as ₹/quintal by convention/inference (Section 4, item 9) |
| Arrival/quantity unit | Explicitly labeled: `Arrivals (Metric Tonnes)` | **Not present in the source at all** — CEDA's `/api/prices` schema has no arrival/quantity field (a separate `/api/quantities` endpoint exists per Phase 3A.2/3A.3 but was never called) |
| Price value type | Values observed as clean multiples of 100 (e.g. 400.0, 800.0, 3000.0) — consistent with a single reported figure per market-day | Non-integer values (e.g. `1266.6666666666667`) — consistent with an averaged figure across multiple mandis per district-day |

**This is a real inconsistency worth flagging plainly:** Tomato's price unit is stated by its source; Potato's is not, and Potato's values additionally represent a different underlying computation (an average, not a single reported price). Treating the two `modal_price_rs_quintal` columns as directly equivalent in a future model without accounting for this would be a mistake this report is flagging in advance.

## 9. Cross-Dataset Compatibility

| Dimension | Tomato | Potato | Compatible? |
|---|---|---|---|
| Data source | Official Agmarknet 2.0 (government), manually exported | CEDA (academic republisher), scripted API pull | 🟡 Different provenance — both ultimately trace to Agmarknet-reported mandi data, but via different pipelines with different aggregation logic |
| Geographic level | Market (Bowenpally APMC) | District (Hyderabad), proxy | 🔴 **Not the same granularity** — this is the single most important incompatibility |
| Market coverage | One specific, named mandi | An unknown mix of mandis within Hyderabad district, averaged | 🔴 Cannot be reconciled without knowing which mandis feed the district figure |
| Date range (in window) | 2025-03-05 to 2025-08-31 (with a 66-day interior gap) | 2025-03-05 to 2025-09-07 (near-complete) | 🟡 Overlapping but unequal — Tomato has no data at all for the last 7 days of the window |
| Units | Explicit ₹/quintal, single reported price per day | Inferred ₹/quintal, averaged price per day | 🟡 Same nominal unit, different underlying computation |
| Available fields | Date, arrival (metric tonnes), variety, min/max/modal price | Date, min/max/modal price only (no arrival/quantity field pulled) | 🔴 Tomato has an arrival-quantity field Potato does not |
| Missing-date pattern | 47.1% missing, dominated by one 66-day structural blackout | 4.8% missing, scattered single days | 🔴 Very different reliability profiles |

**Suitability assessment:**
1. **Descriptive price analysis (e.g., separate summary statistics, separate trend charts per commodity):** ✅ **Usable independently.** Each dataset can be described and summarized on its own terms; nothing here blocks that.
2. **Demand-related modeling:** 🔴 **Not supported by either dataset as delivered.** Potato has no arrival/quantity field at all; Tomato has one, but with a 47% missing-date rate that would badly undermine any demand-side time series. Neither is currently adequate for this use case, and this report does not claim otherwise.
3. **ML experiments (e.g., Phase 3A.1's trend-classification component):** 🟡 **Usable only if the two commodities are modeled as two separate, independently-evaluated series, never merged into one dataset or compared as if measuring the same geography.** A joint or comparative model that treats "Hyderabad district Potato" and "Bowenpally Tomato" as the same kind of observation would misrepresent what was actually measured. Per-commodity models remain viable: Potato has a strong 95%-complete 6-month series; Tomato has a much weaker, gap-heavy series that would need its 66-day blackout explicitly handled (e.g., trained only on contiguous sub-periods) before any credible chronological train/test split.

**This report does not claim Tomato and Potato represent identical geographic granularity, and explicitly documents that they do not (Section 8).**

## 11. Processing Decisions

- **Tomato extraction:** only the `Bowenpally APMC` block was extracted from each monthly CSV; all other markets' rows were read (to correctly delimit section boundaries) but discarded from the processed output, per the task's scope.
- **Restriction to study window:** both processed CSVs are filtered to `2025-03-05 <= date <= 2025-09-07` inclusive. Rows outside this window that exist in the raw files (e.g., Tomato's 2025-03-01 to 2025-03-04) were read and validated as part of full-file structural checks but excluded from the final processed CSV, per the task's explicit scope instruction.
- **No date filling:** every date absent from a raw source is simply absent from the corresponding processed CSV row set — there is no row with an empty/null price for a missing date; the date itself does not appear.
- **No unit conversion:** Tomato's explicit ₹/quintal and Potato's inferred ₹/quintal were both carried through unchanged; no scaling or normalization was applied.
- **No merging:** the two processed files remain fully separate CSVs with different schemas (per Task 3/5's differing column specifications) — they are not joined into one table, consistent with Section 9's finding that doing so would misrepresent geographic granularity.
- **District field for Tomato:** populated as `"Hyderabad"`, sourced from the official Agmarknet reference data confirming Bowenpally APMC's `district_id` maps to Hyderabad (Section 8) — this is an evidence-backed lookup value, not an invented one.

## 13. Limitations

- **Tomato's 66-day blackout is unexplained.** This report does not know, and does not speculate beyond noting the observed fact, whether it reflects a genuine market closure, a reporting failure, or an export/extraction artifact specific to these six files. A future phase could check whether other markets in the same June/July files show a similar drop, which would point toward a source-side reporting issue rather than something Bowenpally-specific — this was not done here, as it is outside this phase's scope.
- **September 2025 Tomato data does not exist in this project at all yet.** If it becomes available later (e.g., a 7th manually-exported file), this script can be re-run without modification to incorporate it — but that has not happened yet.
- **Potato's units are inferred, not confirmed.** If a future phase obtains explicit unit documentation from CEDA, this should be re-verified.
- **Neither processed dataset has been checked against an out-of-band source for accuracy** (e.g., comparing a specific date's Bowenpally Tomato price against a different, independent report) — this validation checked internal consistency (structure, duplicates, chronology, min/modal/max ordering) but not external accuracy.
- **The 103 raw Tomato rows include a small number outside the study window** (2025-03-01 to 2025-03-04) that were parsed and validated but not included in the processed file — this is intentional per Section 11, not an oversight, but is noted here so the "103 parsed" vs. "99 processed" discrepancy is not mistaken for an error.

## 14. Final Verdict

| Dataset | Verdict | Reason |
|---|---|---|
| **Potato (Hyderabad district)** | **ACCEPTED WITH LIMITATIONS** | Clean structurally (zero duplicates, zero ordering violations, zero negative values), covers 95.2% of the target window with only small scattered gaps — but remains a district-level proxy for a mandi-level research question, and its units are inferred rather than source-confirmed. Usable for a per-commodity ML/trend-analysis component with these limitations explicitly carried forward. |
| **Tomato (Bowenpally APMC)** | **ACCEPTED WITH LIMITATIONS** — *bordering on REQUIRES CORRECTION* | Structurally clean where data exists (zero duplicates, zero ordering violations, zero negative values, correct market-level granularity matching this project's original scope) — but only 52.9% of the target window is actually covered, dominated by one 66-day structural blackout plus a fully-missing final week. This is accepted for now because the data that does exist is genuinely clean and correctly scoped, not because the coverage gap is minor — a future ML phase must explicitly decide how to handle the 66-day gap (e.g., restrict training to contiguous sub-periods) rather than treating this as a complete daily series. |

**Neither dataset is REJECTED — both contain real, verifiably clean, correctly-attributed price records — and neither is force-accepted as fully sufficient without qualification.** The two datasets are not compatible for direct comparison or merging (Section 9) and must continue to be treated as two separate, differently-scoped series in any future modeling phase.
