# Backend/core dependencies for the AI-Driven Collaborative Procurement Decision System.
#
# networkx -- added in Phase 6C for the group-formation compatibility graph
#             (connected components, per Phase 2B's graph-based design,
#             reports/phase6c_group_formation_report.md).
# pytest    -- already an implicit dependency of the test suite since
#              Phase 6A; formalized here for completeness, not a new
#              addition in Phase 6C.
# fastapi   -- added in Phase 6F for the HTTP/API boundary layer only
#              (backend/api/); pulls in pydantic (already used for API
#              request/response validation) as its own transitive
#              dependency, so pydantic is not pinned separately here.
# httpx     -- added in Phase 6F; required by Starlette's TestClient
#              (used in tests/api/) to issue in-process HTTP requests
#              against the FastAPI app -- a genuine test dependency, not
#              an unrelated addition.
# psycopg   -- added in Phase 8B for backend/persistence/supabase_repository.py's
#              direct PostgreSQL connection to Supabase (Phase 8A ADR-5:
#              a direct connection, not the Supabase REST client library
#              or handcrafted HTTP calls). The [binary] extra bundles a
#              precompiled libpq, avoiding a system-level PostgreSQL
#              client library dependency. Used synchronously (matching
#              this project's existing entirely-synchronous FastAPI route
#              handlers and repository methods) -- deliberately NOT the
#              already-locally-present `asyncpg` package, since adopting
#              it would force an unrelated, unrequested async conversion
#              across the route/repository layers (see
#              reports/phase8b_supabase_database_foundation.md Section 6).
# PyJWT     -- added in Phase 8D for backend/security/jwt_verifier.py's local
#              (JWKS-based) verification of Supabase access tokens (Phase 8A
#              ADR-4: verify locally, never call Supabase's own
#              /auth/v1/user endpoint per request). Already installed
#              transitively before this phase; pinned here explicitly now
#              that it is a direct, load-bearing dependency. Chosen over the
#              also-installed `python-jose` because PyJWT's own
#              `PyJWKClient` was confirmed (by reading its source) to
#              already implement the exact bounded JWKS cache and
#              "unknown kid -> refresh once -> fail" behavior this phase
#              requires, so no library was added purely to satisfy this
#              phase -- see reports/phase8d_fastapi_jwt_authentication.md
#              Section "Dependencies added". `cryptography` (already
#              installed as a transitive dependency of both PyJWT and
#              psycopg) provides the RS256/ES256 primitives PyJWT uses; it
#              is not listed separately here since nothing in this project
#              imports it directly.
networkx>=3.0
